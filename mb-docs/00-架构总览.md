# 00 · 架构总览（模块索引 + 流程图）

本文是整个项目的**模块索引**：先告诉你项目由哪几个模块（目录）组成、每个模块里有哪些文件、
每个模块"是干什么的、为什么存在、边界在哪"；后半部分用流程图把运行期的几条主线（启动、通道、路由、线程）画出来。
**想深入某个文件，点文件名链接进它的逐篇文档；想看真实代码，点文档顶部的"源文件"链接。**

一句话项目背景：本项目是 **nw.js 的改版**——不携带 nw.js 那套庞大的 Chromium 内核，
改为运行时动态加载 [mb108_x64.dll](../bin/mb108_x64.dll)（miniblink），由一个约 740 KB 的 Win32 小宿主
`nw.exe` 把"内核视图 + Win32 窗口 + 页面里的 nw.\* API"接起来，让已有 nw 应用不改或极少改即可运行。

---

## 模块一览（先看这棵树）

```text
nw\
├─ build-nw.bat          构建入口（不属于任何模块的一条总装命令）
│
├─ src\                  ① native 宿主模块 —— 全部 C++，编译产物就是 nw.exe
├─ generated\            ② 内置脚本生成物 —— embed 工具产出，可删可重建
├─ js\                   ③ 页面注入脚本模块 —— 进窗口里跑的 JS（nw.* API + 纯 JS 版 node）
│   ├─ nw_node.js
│   └─ api\              （12 个按数字前缀排序的模块）
│
├─ tools\                ④ 构建/文档辅助工具模块
├─ tests\                ⑤ 回归测试模块（驱动脚本 + apps\ 被测应用 + .out\ 产物）
├─ reference\            ⑥ 上游 nw.js 只读参考（cc / idl / js，不编译不运行）
├─ archive\              ⑦ 退役历史件归档
├─ mb-docs\              ⑧ 本文档体系（这篇 + 43 篇逐文件文档 + index.html）
└─ bin\                  ⑨ 构建与运行产物（nw.exe + 内核 dll + JS 副本）
```

模块依赖方向（谁离不开谁）：

```text
build-nw.bat ──编译──► src\ + generated\ ──产出──► bin\nw.exe
     ▲                    ▲                              │
     └─调用── tools\      └─脚本来源── js\               │ 运行时
                                            运行时        ▼
                                   bin\nw.exe ◄──拷贝── js\ 副本（优先读盘）
                                      │
                                      ├─ 加载内核 dll（bin\mb108_x64.dll）
tests\ ──黑盒驱动──► bin\nw.exe        └─ 加载 tests\apps\*\package.json
reference\ / archive\ 不参与编译与运行，只供人看
```

## ① src\ —— native 宿主模块（C++，项目的本体）

**职责**：这是项目唯一编译成机器码的部分，产物 `bin\nw.exe`。它对上（进程层）提供自己的
`main()` 与 Win32 消息循环，对下（内核层）用 LoadLibrary + 函数指针表挂接 miniblink，
对外（页面层）通过"内核回调 + 注入 JS"暴露 nw.js 兼容 API。原版 nw.js 里散落在 Chromium
content 层、extensions AppWindow、IDL bindings、真 node 四五个子系统里的职责，
在这个项目里全部收敛到这十几个 C++ 文件中。模块边界：**只写 native 侧逻辑，任何页面可见的
JS API 形状都不在这里定义**（那是 ③ js 模块的事），两者通过 JSON 命令信封解耦。

文件清单：

| 文件 | 干什么 |
|---|---|
| [nw_main.cpp](../src/nw_main.cpp) | 进程入口 `main()`：DPI 感知、解析 `--nwapp/--nw-kernel/--nw-no-node/--nw-no-dialog`、串起 Start/OpenWindow/Run/Shutdown。 |
| [nw_host.h](../src/nw_host.h) | 宿主声明层：`Host` 单例、`NwWindow` 结构（窗口全部镜像状态）、`HostOptions`、`Channel` 枚举。 |
| [nw_host.cpp](../src/nw_host.cpp) | **最大最核心**（约 2300 行）：窗口生命周期、内核回调注册、脚本注入、命令分发 `Dispatch()`、10 组 `Api*` 实现、同步安全闸门（重入红线 + 白名单）。 |
| [nw_kernel.h](../src/nw_kernel.h) | miniblink ABI：`KernelApi` 函数指针表（约 40 个 mb\* 签名）与回调类型。 |
| [nw_kernel.cpp](../src/nw_kernel.cpp) | 内核加载器：候选路径找 dll、`GetProcAddress` 取全部导出、必需导出缺失即失败、全局 `mbInit`。 |
| [nw_rpc.h](../src/nw_rpc.h) / [nw_rpc.cpp](../src/nw_rpc.cpp) | 同步主通道：127.0.0.1 loopback HTTP 服务（随机端口、256bit 令牌、每连接 worker、403/404/413 等协议应答、有序关停）。 |
| [nw_package.h](../src/nw_package.h) / [nw_package.cpp](../src/nw_package.cpp) | package.json 清单解析、应用目录自动定位、Win32 路径与宽窄字符编码工具。移植自 nw.js 同名文件，去掉 Chromium 依赖。 |
| [nw_json.h](../src/nw_json.h) | header-only 极简 JSON（解析+序列化，容忍注释/BOM）。 |
| [nw_script.h](../src/nw_script.h) | 内置注入脚本两个访问函数的声明。 |
| [nw_script_stub.cpp](../src/nw_script_stub.cpp) | 内置脚本的空占位：embed 失败时改编译它（此时 exe 旁必须有 JS 文件）。 |

## ② generated\ —— 内置脚本生成物

**职责**：解决"单文件分发"问题——把 ③ 里的全部 JS 烤进 exe，使 exe 旁边没有 JS 也能启动。
这个模块里的东西**全部是构建产物，不是手写源码**：随时可以删除，下次构建由 tools\embed-js.ps1
自动重建。之所以单独成目录而不是混进 src\，就是为了让人一眼分清"哪些能改、哪些改了会被覆盖"。

| 文件 | 干什么 |
|---|---|
| [nw_script_generated.cpp](../generated/nw_script_generated.cpp) | JS 切片成每片 8000 字符的 C++ 原始字面量数组（避开 MSVC C2026 的 16380 字节静默截断），运行时拼回整串。**勿手改**。 |

## ③ js\ —— 页面注入脚本模块（窗口里运行的 JS）

**职责**：这是"在网页里重建 nw.js SDK"的部分，随每个窗口的脚本上下文注入。它内部分两层：
下层是 `api\` 12 个模块拼成的 **nw.\* API 层**（含通道地基），上层是 `nw_node.js` 的
**纯 JS CommonJS 运行时**（不是真 node：没有 V8 集成、没有原生 .node/child_process/net，
凡是要落操作系统的动作都经 `fs.`/`process.` 等 JSON 命令回到 native）。模块边界：
**这里只做页面侧逻辑与 API 形状，不做任何特权操作**；文件读写、窗口控制等全部以命令形式下发。
关键契约：宿主把 `api\*.js` **按文件名排序拼成一个脚本**并统一包一层 IIFE，所以数字前缀即加载顺序，
单个模块内禁止再套 IIFE、禁止重复 `'use strict'`。

| 文件 | 干什么 |
|---|---|
| [nw_node.js](../js/nw_node.js) | 纯 JS CommonJS 运行时：require 解析（node_modules 上溯、package.json main、node: 前缀）、module 缓存、Buffer/process 与 fs/os/path/url/events 等内置模块；fs 全同步、经 RPC 落 native。 |
| [00_base.js](../js/api/00_base.js) | **通道地基**：rpc/rpcAsync/tell/rpcSafe、三同步通道探测、载荷 base64+percent 编码、Emitter、exposeStatics。所有上层模块都建在它之上。 |
| [10_api_nw_app.js](../js/api/10_api_nw_app.js) | nw.App：argv 过滤、manifest/dataPath、quit、全局热键 id 段、不可用能力的代理空实现。 |
| [15_api_nw_internal.js](../js/api/15_api_nw_internal.js) | internalRead/Tell 分界层：上层模块只碰它、不直接碰通道；白名单镜像对账。 |
| [20_api_nw_window.js](../js/api/20_api_nw_window.js) | nw.Window / WindowState：约 50 个窗口命令；title/zoom 访问器防回声；open 的 id 异步结算与命令排队；capturePage。 |
| [40_api_nw_menuitem.js](../js/api/40_api_nw_menuitem.js) | MenuItem：菜单树递归序列化、分配点击回调 id。 |
| [41_api_nw_menu.js](../js/api/41_api_nw_menu.js) | Menu：增删/插入/popup/attach；点击统一回 `__nmbMenuClick`。 |
| [50_api_nw_clipboard.js](../js/api/50_api_nw_clipboard.js) | 剪贴板：text/html/png/rtf 读写与格式约定（png/rtf 走 base64）。 |
| [51_api_nw_shell.js](../js/api/51_api_nw_shell.js) | openExternal / openItem / showItemInFolder / beep。 |
| [52_api_nw_screen.js](../js/api/52_api_nw_screen.js) | 显示器枚举缓存、displayBoundsChanged（无可靠增删消息源，不发 added/removed）。 |
| [53_api_nw_shortcut.js](../js/api/53_api_nw_shortcut.js) | 全局热键注册表、id 分配、`__nmbHotkey` 回调入口。 |
| [54_api_nw_tray.js](../js/api/54_api_nw_tray.js) | 托盘图标：异步创建 + 图标排队、`__nmbTrayEvent`、右键弹菜单。 |
| [90_install.js](../js/api/90_install.js) | **总装层**：缝出 window.nw、挂 `__nmb*` 事件入口、接管 window.open。 |

# 运行期流程图

## 流程图 1 · 进程启动链（时间从上到下）

```text
[nw_main.cpp] main()
   │  SetProcessDPIAware
   │  CommandLineToArgvW 解析: --nwapp / --nw-kernel / --nw-no-node / --nw-no-dialog
   ▼
[nw_host.cpp] Host::Start()
   │
   ├─ PreparePaths            定 exe 目录 / 应用目录 / 用户数据目录
   │
   ├─ LoadKernel ───────────► [nw_kernel.cpp]
   │                            LoadLibraryExW(mb108_x64.dll)
   │                            GetProcAddress 取约 40 个 mb* 导出 -> KernelApi 表
   │                            mbInit()                       (必需导出缺失即启动失败)
   │
   ├─ LoadManifest ─────────► [nw_package.cpp] 读 apps\xxx\package.json -> Manifest
   │
   ├─ LoadScripts            读 js\api\*.js + js\nw_node.js
   │                            └─读不到则用 generated 内置副本 (nw_script_generated.cpp)
   │
   └─ RpcServer::Start ─────► [nw_rpc.cpp] bind 127.0.0.1:随机端口 + 256bit 令牌
                                (失败不致命: 页面后续退回 prompt 通道)
   ▼
Host::OpenWindow()
   │  注册窗口类 -> CreateWindowEx 建 Win32 框架窗
   │  mbCreateWebView
   │  mbSetHandle(view, hwnd)        ★内核控件窗嵌为框架窗的真实子窗口
   │  注册内核回调: jsQuery / loadUrlBegin / promptBox /
   │               scriptContext / documentReady / title / url / console / close / createView
   │  mbLoadURL(manifest.main)
   ▼
内核回调 OnScriptContext / OnDocumentReady（幂等，两个时机各注入一次）
   └─ InstallScripts(): preamble(__nwWindowId / __nmbRpcPort / __nmbRpcToken /
                                  __nmbBootAppReply / __nmbBootProcessReply …)
                        + api\*.js 拼接体 + nw_node.js
   ▼
Host::Run()  ◄════ GetMessage / TranslateMessage / DispatchMessage 循环 ════►
   │            （HostWndProc 处理尺寸/菜单/热键/托盘/显示变化；直到 WM_QUIT）
   ▼
Host::Shutdown(): 停 RPC(join 线程) -> 关内核视图 -> 释放 dll
```

## 流程图 2 · 页面 ↔ native 的四条通道

miniblink 没有"同步绑定 JS 函数"的导出，而 mbQuery 的应答在后续任务才投递、同步读拿不到，
因此同步取数与异步动作分成四条路：

```text
                 页面 JS  (js\api\*.js)
 ┌───────────────────────────────────────────────────────────────┐
 │  同步取数 rpc() —— 启动时 probeSyncChannel() 探测, 探通谁用谁:  │
 └───────────────────────────────────────────────────────────────┘
   │
   ├─① loopback HTTP【主】  00_base.js loopbackOnce
   │     同步 XHR POST  http://127.0.0.1:<随机端口>/w<窗口id>/?t=<令牌>
   │                                  │
   │                                  ▼
   │                     [nw_rpc.cpp] accept 线程 -> 每连接 worker 线程
   │                                  │  令牌/来源校验 (错=>403)
   │                                  ▼
   │                     Host::Dispatch(Channel::Sync)  ◄── 仅白名单命令可跑
   │
   ├─② prompt 拦截【退路】  promptOnce (最多 3 次重试)
   │     window.prompt("__nmb_rpc__:" + payload)
   │                                  ▼
   │                     [nw_host.cpp] OnPromptBox  (UI 线程, 唯一同线程的同步路)
   │
   ├─③ 伪URL 同步XHR【老内核退路】 xhrOnce
   │     nmb-rpc: | /__nmb_rpc__/ | http://nmb-rpc/
   │                                  ▼
   │                     [nw_host.cpp] OnLoadUrlBegin (内核网络线程, 当场作答)
   │                     (mb108 不回调此钩子; 留给 mb132 等老内核)
   │
   └─④ mbQuery【异步, 动手类操作】 rpcAsync() / tell()
         mbQuery(id, json)
                                    ▼
                       [nw_host.cpp] OnJsQuery (UI 线程)
                                    ▼
                       Host::Dispatch(Channel::Async) -> 全部 Api*

   ◄════════════ 统一应答信封 { "s":"ok", "v":… } / { "s":"err", "m":… } ═══════════►
              载荷编码三路统一: encodeURIComponent( btoa( UTF8字节 ) )
```

## 流程图 4 · 线程模型

```text
┌─────────────────────── UI 线程（主线程, 一个）────────────────────────┐
│ Win32 GetMessage 循环 (Host::Run)                                     │
│ 内核回调: OnJsQuery(异步通道④) OnPromptBox(同步退路②)                  │
│           OnScriptContext OnDocumentReady OnTitleChanged …           │
│ HostWndProc: 尺寸/菜单/热键/托盘/显示变化                              │
│ Dispatch(Async) 与全部 Api* 的窗口/菜单/托盘操作都在这里执行            │
└───────────────────────────────────────────────────────────────────────┘
            ▲ 唯一被允许在同步路径里碰 UI 命令的通道 = ②prompt（同线程）
            │
┌─────────────────────── loopback 线程组（nw_rpc.cpp）──────────────────┐
│ accept 线程: 非阻塞监听 + select 200ms 轮询 running_ 标志              │
│    └─ accept 到连接 => 派一个一次性 worker 线程                        │
│          worker: 读 HTTP 请求 -> 校验令牌/来源 -> Dispatch(Channel::Sync)
│          （非 UI 线程, 因此永远只能跑到 SyncSafeCommand 白名单）        │
└───────────────────────────────────────────────────────────────────────┘
┌─────────────────────── 内核网络线程（miniblink 内部）──────────────────┐
│ OnLoadUrlBegin: 同步退路③ 的伪 URL 在此当场作答                        │
└───────────────────────────────────────────────────────────────────────┘

 三个线程号运行时记入原子量 g_threadMain / g_threadUi / g_threadSync，
 transport 类型记入 g_syncTransport，并随 app.info.threads 报给页面自检。
```

# split_api.py —— 一次性重构脚本：单体 nw_api.js 拆成 js\api\ 多模块

- 源文件：[archive/split_api.py](../../archive/split_api.py)
- 角色：**历史工具，已执行完毕，正常构建不调用它。** 把旧的单文件页面脚本
  [nw_api.js](../src/nw_api.js.md) 按 nw.js SDK 的模块边界拆成了 [js/api/](../../js/api/) 下的多模块。

## 它做了什么（文档价值）

- 只做"按行范围搬家 + 给每个新文件加文件头注释"，**不改变任何语句**；语义改动（title/zoomLevel
  访问器、internal 绑定层等）在搬家之后单独做；
- 文件里写死了每个目标模块对应的**原文行号区间**（`sl(a, b)`，1 起含两端），
  并带"反向拼回与原文逐行比对"的双向自检，证明搬迁没丢语句；
- 每个新文件头写清它对应 SDK 的哪个 `api_nw_*.js`。

## 拆完后的前提（至今仍约束 js/api/ 目录）

宿主把 `js\api\*.js` **按文件名排序拼成一个脚本**，外面统一包一层 IIFE（`window.__nmbInstalled`
幂等守卫）。因此：

- 各模块共享同一个函数作用域——单模块内不要再套自己的 IIFE，也别重复 `'use strict'`；
- 文件名数字前缀（00/10/15/20/…/90）就是加载顺序。

## 现状

跑完即可删除的一次性工具，但保留它可以让后来者追溯"某个函数最初在旧单体文件的哪一段、
为什么落在现在这个模块"。想继续拆/并模块时可参考其写法。
